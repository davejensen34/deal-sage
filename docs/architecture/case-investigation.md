# Case investigation UI

Issue #162 is the first 8.3 slice, following discovery runs and the query-capacity usability fix. The case page reads `/api/research/cases/{case_id}/investigation/sources`, `/evidence` and `/evidence/{evidence_id}/claims`. Each collection uses 20-record pages with explicit next-page availability. All reads require authenticated pilot access; same-case evidence/source checks reject cross-case identifiers.

An analyst may record an access decision with a rationale. Approval additionally requires an explicit statement that access conditions were reviewed. Recorded authentication, paywall, CAPTCHA, robots or reuse restrictions block approval. These are access judgments, not claim validation, permission to spend, source promotion or automatic network retrieval. Blocked clues remain visible for research; lack of evidence does not disprove a claim.

`SearchService.decide_access` claims only a pending SQL row, then commits the decision and user-linked audit together. This protects against concurrent reviewers holding stale ORM objects. Decisions retain their original actor, rationale and time and cannot be overwritten; a repeated submission reports a conflict and the UI can reload the retained decision. The existing retrieval service continues to enforce approval and access restrictions independently.

Evidence inspection shows publisher, classification, source URL, publication date in UTC, local retrieval timestamp, bounded plain-text excerpt, content hash and raw artifact ID. Missing artifact linkage is stated rather than inferred. It exposes no storage key, raw bytes, internal provenance dictionary or request metadata. Claim inspection retains source classification/status, subject, predicate, object, relationship semantics, authority and directness. Executive and registered-agent roles do not become ownership. Excerpts and claim objects render as text, never HTML; only HTTP(S) links are clickable. Publication/retrieval dates do not establish event dates; multiple documents do not establish source independence.

This slice makes no external calls and changes no discovery budget or database schema. Bounded retrieval/extraction, frontier execution, explicit independence inspection and versioned brief updates remain 8.3 work. A case must still complete the approved 8.1→8.3 journey before 8.4 expansion. Prior failed/unmeasured live quality outcomes remain intact.
