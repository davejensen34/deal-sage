# Case investigation UI

Issue #162 is the first 8.3 slice, following discovery runs and the query-capacity usability fix. The case page reads `/api/research/cases/{case_id}/investigation/sources`, `/evidence` and `/evidence/{evidence_id}/claims`. Each collection uses 20-record pages with explicit next-page availability. All reads require authenticated pilot access; same-case evidence/source checks reject cross-case identifiers.

An analyst may record an access decision with a rationale. Approval additionally requires an explicit statement that access conditions were reviewed. Recorded authentication, paywall, CAPTCHA, robots or reuse restrictions block approval. These are access judgments, not claim validation, permission to spend, source promotion or automatic network retrieval. Blocked clues remain visible for research; lack of evidence does not disprove a claim.

`SearchService.decide_access` claims only a pending SQL row, then commits the decision and user-linked audit together. This protects against concurrent reviewers holding stale ORM objects. Decisions retain their original actor, rationale and time and cannot be overwritten; a repeated submission reports a conflict and the UI can reload the retained decision. The existing retrieval service continues to enforce approval and access restrictions independently.

Evidence inspection shows publisher, classification, source URL, publication date in UTC, local retrieval timestamp, bounded plain-text excerpt, content hash and raw artifact ID. Missing artifact linkage is stated rather than inferred. It exposes no storage key, raw bytes, internal provenance dictionary or request metadata. Claim inspection retains source classification/status, subject, predicate, object, relationship semantics, authority and directness. Executive and registered-agent roles do not become ownership. Excerpts and claim objects render as text, never HTML; only HTTP(S) links are clickable. Publication/retrieval dates do not establish event dates; multiple documents do not establish source independence.

This slice makes no external calls and changes no discovery budget or database schema. Bounded retrieval/extraction, frontier execution, explicit independence inspection and versioned brief updates remain 8.3 work. A case must still complete the approved 8.1→8.3 journey before 8.4 expansion. Prior failed/unmeasured live quality outcomes remain intact.

Issue #164 subsequently adds [explicit durable document retrieval](retrieval-attempts.md) to approved sources and shows attempt history below evidence. The prior no-execution statement describes #162; discovery budgets remain frozen and the retrieval action has its own one-document authorization.

## Source independence inspection

The subsequent [cited extraction increment](cited-extraction.md) (#168) adds explicit packet preview, bounded model execution, durable recovery and quoted model-proposal history to retained evidence. It does not promote model output into source claims or close the full 8.3 acceptance gate.

Issue #166 adds authenticated `GET /api/research/cases/{case_id}/investigation/evidence/{evidence_id}/comparisons?page=1`. Each page compares the selected item against at most twenty other case-local evidence records, ordered by ID, including items beyond the visible evidence page. It reads the existing deterministic `evidence_relationship` classifier; it does not create `EvidenceRelationship` rows, audit judgments, scores or network requests. The endpoint rejects cross-case evidence IDs. Comparison details load only when the reviewer expands the control.

The `evidence-pair-inspection-v1` presentation distinguishes identical hashes, shared syndication provenance, normalized publisher matches and no observed shared provenance. The last outcome is explicitly **not verified independent reporting**. Empty hashes/publisher names cannot establish duplication or independence; incomplete legacy imports display unknown when the selected rule lacks its required input. Valid identical hashes or shared story provenance can still establish dependence despite missing publisher names. Existing scoring rules and retained classifications remain unchanged.

Only counterpart evidence ID, publisher, public source URL, classification, rule key and a fixed explanation are returned. Internal provenance values, original-story identifiers and request metadata are excluded. Source-provided text renders as text, and only HTTP(S) links are clickable. Comparisons say nothing about whether a claim is true, an individual owns a business or a business is for sale.

Validation: 501 backend/API tests and 39 frontend tests passed, with TypeScript/production build (existing chunk warning). Tests cover all classification paths, missing provenance, case isolation, viewer/authentication boundaries, pagination, absence of relationship/audit writes, safe rendering and read-failure retry. A fictional six-document comparison case was inspected at desktop and 390px widths. No live calls, operational-corpus changes or schema migration ran. Extraction, frontier execution and versioned insights remain open 8.3 work.
