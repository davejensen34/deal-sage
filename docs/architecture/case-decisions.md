# Reviewer workflow decisions

Issue #174 is the first Milestone 8.4 increment. A reviewer records `more_research`, `monitor` or `dismiss` for acquisition exploration, marketing introduction or succession advisory. These are human workflow intentions, separate from source claims, model dispositions, `AnalystConclusion` evidence judgments and candidate status. Monitoring intent schedules nothing; dismissal does not stop research execution. Issue #176 adds development-brief creation, contact readiness and reviewed export as described below.

## Version and correction contract

A decision references one immutable saved brief in the same case. The reviewer supplies rationale, next action, purpose and optional supporting/contradicting source IDs from that exact version. Empty evidence remains permissible for an explicitly explained lack-of-evidence decision. A source cannot occupy both selections; mixed evidence belongs in the rationale. Membership validates provenance, not source truth or ownership. Later evidence does not silently move a decision to a newer brief.

`CaseDecision` retains content, actor, stable actor key, brief ID, request UUID and prior decision ID. Recording a replacement requires the latest decision ID and a change reason. A case-row write serializes the chain, including its first row. Stale submissions conflict; identical actor/case/payload/request retries return the original committed result even after a later correction. Previous decisions remain unchanged. Decision and audit commit together, without source/model calls, candidate promotion or research-state mutation. Stopped cases may still receive human review.

Authenticated `GET /api/research/cases/{id}/decisions?page=1` provides the latest decision and ten history entries per page. `POST` requires review permission. There is no update/delete endpoint. Migration `b174a0b1d837` follows the follow-up migration and refuses a downgrade that would discard retained decisions. This is the existing single-organization authorization boundary, not tenant isolation.

## UI and observed validation

Case pages show the current decision and history. Reviewers load a specific saved brief version, inspect its retained source excerpts, select references and submit the decision. Loading a brief refreshes the current decision to recover from a conflict. A lost response retries the same payload/UUID. Viewers have read access only. The saved brief remains unchanged; workflow history is linked alongside it rather than copied back into that snapshot. Existing inbox filters and monitoring schedules are unchanged.

All 535 backend/API tests passed. All 46 frontend tests, TypeScript and the production build passed (existing chunk warning). Tests cover exact source/version membership, unsupported/mixed selections, no research-state mutation, correction history, stale submissions, actor-safe request replay, permissions, pagination and migration/reopen/downgrade protection.

The isolated fictional demo recorded more research against brief version 1, then replaced it with monitor and an explicit reason. Both decisions, author, source selections and next actions survived reload. Desktop and 390px layouts were inspected. Only the isolated demo received the migration; no live calls or operational-corpus changes ran. This does not complete 8.4 or the actual human usefulness gate.

## Opportunity-development handoffs (#176)

`create_development_brief` stores a required development payload in the existing immutable decision JSON. It contains reviewer-authored opportunity summary, explicit unknowns, readiness and readiness rationale. Purpose, decision rationale, next action and supporting/contradicting evidence IDs remain on the decision. The linked saved brief is the frozen evidence/model/human basis; no second evidence corpus or migration is needed. Corrections use the existing append-only chain and stale-submit checks. The optional new field is omitted for legacy requests so their request-key recovery remains compatible.

A contact is optional for `not_ready`; absence stays unknown. `reviewer_ready` requires a reviewer-selected public business contact and explicit public-business-use attestation. Contact records contain recipient/team, channel, literal value, exact quotation and evidence ID. Both quotation and value must occur in the retained excerpt from that exact saved brief. This establishes text provenance only: it does not verify identity, consent, public-business suitability or readiness. Those remain named reviewer judgments. Publication/retrieval dates come from the frozen source; review time comes from the decision. Missing publication dates remain unknown. No family contact is inferred from an obituary. New contact evidence outside a saved version requires a new saved brief.

Authenticated `GET /api/research/cases/{case_id}/decisions/{decision_id}/development-brief` joins the retained decision and saved brief. It also reports the immediate superseding decision, if any, without rewriting the historical payload. `POST .../development-brief/export` requires the existing `export` permission, records an attributable audit event and returns an attachment as inert UTF-8 plain text with `no-store` and `nosniff`. The text begins with the human assessment, uncertainty, next action and contact provenance, followed by the complete frozen source/model/human basis. It is an internal reviewed handoff, not a sale claim or outbound message. A historical export retains its original basis and labels its supersession as of download time.

The case UI provides the handoff fields, retained display, unknown-contact state and export button. Viewers can read but cannot create or export. It reuses explicit brief loading and same-payload retry. The existing 200-record/256000-byte saved-brief limits bound the export basis; it does not fetch fresh evidence or run providers.

Validation: all 539 backend/API tests and 49 frontend tests passed; TypeScript and production build passed with the existing chunk warning. New coverage exercises contact/readiness and version membership, legacy recovery, immutable historical basis after source changes/corrections, export permissions and audit, and frontend payload/retry/read-only behavior. Desktop/390px fictional forms, unknown-contact and cited-contact handoffs, save/reload and actual downloaded text were inspected. This completes the M8.4 engineering increment; it does not establish real reviewer usefulness or communication consent. No live calls, operational-corpus writes or schema migration ran. M8.5 monitoring and M8.6 human quality gates remain open.

## Optional review feedback (#182)

Decisions may include usefulness (`useful`, `not_useful`, `not_assessed`), a reason and optional integer review seconds (1-86400). Assessed usefulness requires a meaningful reason. Feedback belongs to the exact purpose, brief and reviewer decision; corrections append and missing feedback remains unmeasured. Omitted feedback is excluded from legacy payloads so existing request retries still match. The existing review permission, audit and transaction boundary apply. Loading a different brief clears draft feedback. See [case workflow measures](case-workflow-measures.md) for reporting denominators and validation.
