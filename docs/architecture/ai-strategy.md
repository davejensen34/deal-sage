# AI strategy

Use models only when they materially improve unstructured extraction, contextual interpretation, ambiguity analysis, evidence synthesis, or research planning. Deterministic code owns scoring arithmetic, validation, persistence, audit behavior, filtering, and state changes.

An `AIProvider` boundary defines extraction, summarization, and match-analysis capabilities. OpenAI and Anthropic adapters implement bounded summarization and JSON-Schema-validated structured extraction. Candidate evidence summary is optional, versioned, logged, evidence-bounded, and forbidden from changing confidence scores.

The local Compose image includes both optional SDKs but provider use remains disabled without an explicit provider and its key. Requests have timeout and output-token limits. OpenAI response storage is explicitly disabled because evidence packets can contain personal information. Provider exception bodies are not persisted because they may echo submitted evidence or request metadata. A synthetic smoke command requires an explicit live-call flag and makes exactly one call; automated tests never spend API credits.

Actual validation state: credential-free operation and adapter request construction are tested without network access. Local synthetic calls validated connectivity to OpenAI `gpt-5-mini` and Anthropic `claude-sonnet-4-5`. Both providers then processed the same approved seven-case public-evidence cohort using native structured-output paths. On the corrected and final allowed attempt, Anthropic returned 7/7 schema-valid results and OpenAI returned 5/7; only 3/14 top-level labels matched the pre-label because the version-one taxonomy conflated independent case dimensions. This validates connectivity, bounded execution, and parts of the integration contract, not comparative reasoning quality. See the [validation results](../research/milestone-3-1-live-validation-results.md).

The version-two [model evaluation contract](model-evaluation.md) now separates case origin, identity resolution, relationship/timeline, operating status, contradiction state, and research disposition; represents incomplete/refusal/invalid/failed outcomes explicitly; and retains separate input/output token usage. Its seven fictional shapes and adapter mocks pass offline. The approved public cohort has reached its call ceiling and cannot be rerun without a new explicit protocol decision.

Never store hidden chain-of-thought. Retain structured results, useful analyst-facing rationale, provider/model/task/prompt version, timestamp, latency, token usage when available, and outcome.

Milestone 4 uses an immutable `ModelProposal` record as the durable boundary between one bounded provider execution and later analyst disposition. Completed proposals require case-local evidence or claim lineage and safe structured output. Incomplete, refusal, invalid, and failed executions retain provenance, usage, latency, cost, and a safe error class but never persist the provider payload or exception body. This proposal record remains distinct from source claims, DealSage confidence, and human conclusions.

Business extraction and ambiguity analysis receive a minimal packet containing only selected case evidence excerpts, extracted facts, and normalized claims. Each proposed business observation cites packet evidence, and any cited claim must derive from that observation's cited evidence. Identity resolution requires a non-name support dimension; relationship and effective-time values must be compatible; and a current-owner proposal requires an explicit owner or co-owner claim. Registered-agent and executive claims cannot be promoted to ownership. Outputs that fail these checks are retained only as invalid execution metadata.

Milestone 4.3 joins discovery and analysis into a bounded loop without collapsing their trust boundaries. Search providers return untrusted candidates; deterministic URL and source-access checks decide whether retrieval may occur; retrieved content is hashed and landed as evidence before a model can see it; model-produced research plans remain immutable proposals until deterministic code approves a bounded frontier action. The loop stops on convergence, exhausted attempts, safety constraints, or any query, document, model, step, elapsed-time, or cost limit. A model never receives credentials, directly invokes an unrestricted browser, promotes a snippet to evidence, or decides that its own proposal is validated.
